# Dental Bot — Telegram-бот для стоматологической клиники (MVP)

Бот принимает сообщения пациентов, классифицирует их через AI (категория,
краткая суть, нужен ли администратор), сохраняет как заявки в БД и
уведомляет администраторов. Администраторы могут смотреть список заявок,
менять их статус и отвечать пациентам прямо из Telegram.

**Бот не ставит диагнозы и не даёт медицинских рекомендаций** — это жёстко
прописано в системном промпте AI-классификатора (`app/ai/prompts.py`).

## Архитектура

```
app/
├── config.py              # настройки из .env
├── bot/
│   ├── main.py             # точка входа бота (Bot, Dispatcher, роутеры)
│   ├── keyboards.py         # инлайн-клавиатуры
│   ├── states.py             # FSM-состояния (сценарий ответа админа)
│   └── handlers/
│       ├── patient.py       # приём сообщений от пациентов
│       └── admin.py         # /requests, смена статуса, ответ пациенту
├── ai/
│   ├── client.py            # обёртка над OpenAI-совместимым API
│   ├── prompts.py            # системный промпт классификатора
│   ├── schemas.py            # Pydantic-схема ответа AI
│   └── classifier.py         # классификация + валидация + fallback
├── db/
│   ├── models.py             # SQLAlchemy-модели (Patient, Request)
│   ├── database.py           # engine, сессии, создание таблиц
│   └── repository.py         # все SQL/ORM-запросы проекта
└── services/
    ├── request_service.py    # связка AI-классификации и сохранения заявки
    └── notification.py       # рассылка уведомлений админам
```

## Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

## Настройка `.env`

| Переменная | Как получить |
|---|---|
| `BOT_TOKEN` | Напишите `@BotFather` в Telegram → `/newbot` |
| `DATABASE_URL` | По умолчанию SQLite, менять не обязательно для MVP |
| `LLM_API_KEY` | Ключ вашего OpenAI-совместимого провайдера |
| `LLM_API_BASE_URL` | Оставьте пустым для OpenAI, иначе — URL вашего провайдера |
| `LLM_MODEL` | Название модели, например `gpt-4o-mini` |
| `ADMIN_TELEGRAM_IDS` | Ваш Telegram ID через запятую (узнать через `@userinfobot`) |

## Запуск

```bash
python init_db.py     # создать таблицы (один раз)
python run_bot.py     # запустить бота
```

## Как проверить, что всё работает

1. **Как пациент**: напишите боту любое сообщение, например "Хочу записаться на чистку зубов".
   Бот должен ответить подтверждением с номером заявки.
2. **Как администратор** (если ваш Telegram ID в `ADMIN_TELEGRAM_IDS`):
   вы должны получить карточку новой заявки с кнопками "Ответить" и статусами.
3. Команда `/requests` в чате с ботом (от админ-аккаунта) должна показать список новых заявок.
4. Нажмите "Ответить пациенту" → напишите текст → пациент должен получить ваше сообщение.
5. Проверьте базу напрямую:
   ```bash
   sqlite3 dental_bot.db "SELECT id, category, status, needs_human FROM requests;"
   ```

## Известные ограничения MVP (не баги, а осознанные границы)

- Один бот = одна клиника (мультиклиника — следующий шаг после MVP, см. план).
- Нет rate-limiting на пользователя — при коммерциализации нужно добавить.
- Если админ пишет боту текст вне сценария "Ответить", это сообщение попадёт
  в обработчик пациента (создастся лишняя заявка от имени админа) — для
  внутреннего тестового аккаунта не критично, но стоит поправить перед продакшеном.
- AI-классификация полагается на инструкции в промпте, а не на "железные"
  ограничения — для реального медицинского контекста стоит добавить
  дополнительный код-фильтр поверх ответа AI (эвристика на медицинские
  термины → принудительно `needs_human=true`), это не реализовано в MVP.

## Дальнейшее развитие (после MVP)

- FastAPI-обёртка поверх `app/services/` для внешнего API.
- Таблица `clinics` + `clinic_id` в `requests`/`patients` для мультиклиники.
- API-ключи, лимиты запросов, платные тарифы.
- Переход с SQLite на PostgreSQL (меняется только `DATABASE_URL`, код ORM не трогаем).
